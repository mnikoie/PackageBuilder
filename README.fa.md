## چه کار می‌کند

مسیرِ یک پوشه را می‌دهی. فهرستی از تصمیم‌ها را نشان می‌دهد — زبان، مدیرِ پکیج، فرانت، بک‌اند، دیتابیس و مانندِ این‌ها — با گزینه‌های واقعیِ هر کدام. یکی را انتخاب می‌کنی و دکمه می‌زنی. ابزار، CLIِ رسمیِ خودِ آن تکنولوژی را در ترمینالی واقعی که جلوی چشمت است اجرا می‌کند، و آن مقدار چسبی را که هیچ CLIای برایت انجام نمی‌دهد اضافه می‌کند: متغیرهای محیطی، پورت‌ها، وصل‌کردنِ سرویس‌ها، و ثبتِ خودِ تصمیم.

هر تصمیمی را می‌شود پس گرفت.

## ایدهٔ اصلی

بیشترِ ابزارهای مشابه، وضعیت را از رویِ فایلِ کانفیگ می‌خوانند. ولی «چیزی که باید نصب باشد» با «چیزی که نصب است» یکی نیست. نامِ یک پکیج در `package.json` یعنی اعلام شده، نه اینکه روی دیسک هست. سرویسی در `docker-compose.yml` یعنی نوشته شده، نه اینکه بالاست.

این ابزار فقط چیزی را گزارش می‌کند که بتواند ثابتش کند، و **سه** جواب دارد نه دو:

| | معنی |
|---|---|
| ✓ | مدرک دیدیم که هست — پوشه در `node_modules`، خطی در خروجیِ `docker compose ps`، یک `.venv` واقعی |
| ✗ | مدرک دیدیم که نیست |
| ؟ | نتوانستیم بپرسیم (Docker بالا نبود، فایلی خوانده نشد) |

«نامعلوم» هرگز بی‌سروصدا به «هست» یا «نیست» ترجمه نمی‌شود. همین یک تفاوت، دلیلِ وجودِ این ابزار است.

## قاعده‌هایی که رعایت می‌کند

- **بی‌مدرک ادعا نمی‌کند.** بودنِ نام در یک فایلِ کانفیگ مدرک نیست.
- **هیچ چیزی پنهان اجرا نمی‌شود.** هر فرمان در ترمینالِ واقعیِ داخلِ صفحه اجرا می‌شود، با خروجیِ کاملش.
- **هیچ تصمیمی تحمیل نمی‌شود.** فایلِ یک تکنولوژی فقط بعد از انتخابِ خودت ساخته می‌شود. پروژهٔ نوساخته هیچ فریم‌ورک و دیتابیس و ابزارِ بیلدی ندارد.
- **هر کاری برگشت‌پذیر است.** هرچه نصب می‌شود حذف هم می‌شود، و بعدِ حذف در فهرست می‌ماند تا دوباره بتوانی نصبش کنی.
- **کارِ تو بازنویسی نمی‌شود.** اگر فایلی از قبل باشد، دست نمی‌زند و به تو می‌گوید.

## شروعِ سریع

به Node.js نسخهٔ ۲۰ به بالا نیاز دارد، و اگر سرویسِ دیتابیس یا جستجو می‌خواهی، به Docker Desktop.

```bash
npm install
npm start
```

بعد `http://127.0.0.1:4600` را باز کن.

خط‌فرمان هم دارد:

```bash
node src/cli.mjs new ./my-app --name "برنامهٔ من"   # ساختِ اسکلت
node src/cli.mjs probe ./my-app                     # وضعیتِ واقعی، فقط‌خواندنی
node src/cli.mjs stack ./my-app                     # تصمیم‌ها و گزینه‌ها
node src/cli.mjs apply ./my-app --tech postgres     # اعمالِ یک تصمیم
node src/cli.mjs revert ./my-app --tech postgres
```

روی ویندوز، `start-server.bat` و `stop-server.bat` هم برای راحتی هستند.

## چه چیزهایی می‌توانی انتخاب کنی

۱۵ دسته و ۳۷ تکنولوژی. هر کدام یک‌بار واقعاً روی پوشهٔ خالی نصب شده و با مدرکِ واقعی سنجیده شده — نه اینکه فرض شود کار می‌کند.

| دسته | گزینه‌ها |
|---|---|
| زبان / رانتایم | Node.js · Python |
| مدیرِ پکیج | pnpm · npm |
| ساختارِ مخزن | Turborepo · Nx · فقط pnpm workspaces |
| فرانت | React Router v7 · Next.js · Vite + React |
| استایل | Tailwind CSS · Bootstrap |
| بک‌اند | NestJS · Express · Fastify |
| سبکِ API | REST + OpenAPI · tRPC · GraphQL |
| سرویسِ AI / پردازشِ فارسی | Python + FastAPI · Node.js |
| احرازِ هویت | Clerk · Auth.js |
| پردازشِ پس‌زمینه | BullMQ · Celery |
| دیتابیس | PostgreSQL · MySQL · MongoDB · MariaDB · SQLite |
| جستجو | Meilisearch · Elasticsearch |
| ذخیره‌سازیِ فایل | MinIO · S3 |
| لاگ و مانیتورینگ | Sentry + pino · خودمیزبان (Grafana/Loki/Prometheus) |
| تستِ سرتاسری | Playwright · Cypress |

اضافه‌کردنِ تکنولوژیِ نو یعنی اضافه‌کردنِ یک ردیفِ داده، نه دست‌بردن در موتور.

## امنیت

این سرور می‌تواند فرمان اجرا کند، پس با اینکه لوکال است جدی گرفته شده:

- فقط روی `127.0.0.1` گوش می‌دهد
- برای هر کاری که اثر دارد، فقط `POST` می‌پذیرد
- توکنِ تصادفیِ هر اجرا لازم دارد که فقط داخلِ صفحهٔ خودش تزریق می‌شود، پس سایتِ دیگری نمی‌تواند بخواندش
- مبدأِ درخواست (`Origin`) را با `Host` می‌سنجد

## از چه ساخته شده

Node.js، بدونِ مرحلهٔ بیلد. `node-pty` برای ترمینالِ واقعی، `xterm.js` برای نمایشش، `ws` برای پُل، و خودِ `node:http` برای سرور. کلِ رابطِ کاربری یک فایلِ HTML است — عوضش کن و صفحه را refresh کن.

```
src/
  cli.mjs            خط‌فرمان
  core/
    scaffold.mjs     ساختِ اسکلتِ مستقل از تکنولوژی
    detect.mjs       تشخیصِ سه‌حالتی، فقط‌خواندنی
    registry.mjs     ۱۵ دسته و ۳۷ تکنولوژی — داده، نه کد
    resolve.mjs      سنجشِ مدرک‌ها روی پروژهٔ واقعی
    apply.mjs        اعمال و برگشتِ تصمیم‌ها
  server/
    server.mjs       http و وب‌سوکت و لایه‌های امنیت
    terminal.mjs     پاورشلِ واقعیِ همیشه‌زنده
    public/index.html  کلِ رابطِ کاربری
```

## تست‌ها

```bash
npm test      # ۲۱۴ تستِ واحد
npm run e2e   # ۱۰ تستِ مرورگر روی سرورِ واقعی
```

تست‌های سرتاسری به ظاهرِ صفحه قناعت نمی‌کنند: خودشان `docker ps` می‌زنند و `pg_isready` را داخلِ کانتینر اجرا می‌کنند. سبزبودنِ تست باید مدرک باشد، نه تزیین.

## وضعیت

کار می‌کند و روزانه استفاده می‌شود. پلتفرمِ آزمایش‌شده ویندوز است؛ لایهٔ ترمینال بر پایهٔ PowerShell است، پس لینوکس و مک هنوز پشتیبانی نمی‌شوند.
