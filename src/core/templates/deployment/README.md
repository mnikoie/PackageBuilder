# استقرار

کانفیگِ اجرای پروژه در محیطِ واقعی و محیطِ لوکال: `docker-compose.yml`،
`Dockerfile`ها، یا هر چیزی که سرویس‌های جانبی را بالا می‌آورد.

**عمداً خالی است.** محتوایش کاملاً به تصمیم‌های ۹ تا ۱۱ (دیتابیس، جستجو،
ذخیره‌سازی) بستگی دارد. ساختنِ یک `docker-compose.yml` از قبل، یعنی انتخابِ
Postgres و Redis و بقیه — قبل از اینکه واقعاً انتخاب شده باشند.

## یک نکتهٔ عملیِ مهم برای وقتی که Docker Compose اضافه شد

فیلدِ `name:` در بالای `docker-compose.yml` باید **یکتا و برابرِ نامِ همین
پروژه** باشد. Docker کانتینرها را با آن نام گروه می‌کند، نه با مسیرِ پوشه.
اگر چند کپی از یک قالب همه `name` پیش‌فرض را داشته باشند، همه یک پروژهٔ
مشترکِ Docker حساب می‌شوند: کانتینرِ یکی، دیگری را «بالا» نشان می‌دهد، و
`docker compose down` در یک پوشه، سرویسِ پوشهٔ دیگر را می‌خواباند.
